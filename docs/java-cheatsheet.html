Java dans Neovim

Les gestes du quotidien, avec leur équivalent IntelliJ en regard — le temps que les réflexes se déplacent. Tout ce qui suit a été testé sur ce poste ; ce qui manque encore est signalé en fin de page.

Avant d'ouvrir

cd ~/src/tsp-solver && nvim src/main/java/com/tsp/Main.java

Le cd n'est pas cosmétique : init.lua:642 nomme le workspace jdtls d'après getcwd(). Lancer nvim depuis ailleurs mélange les workspaces entre projets. java doit être dans le PATH — c'est ton .zshrc qui s'en charge.

Construire

:!mvn -q compile                    " compiler
:!mvn -q package -DskipTests        " fat JAR → target/tsp-solver.jar
:!java -jar target/tsp-solver.jar   " exécuter

Espacedb Poser / retirer un breakpoint sur la ligne Ctrl+F8

Ce que F5 propose sur tsp-solver

  • Launch tsp-solver: com.tsp.Main

Tester jdtls découvre les classes et méthodes de test

Espacetm Lancer la méthode de test sous le curseur Ctrl+⇧+F10
Espacetc Lancer toute la classe de test Ctrl+⇧+F10
EspacedbpuisEspacetm Débugger un test — les deux passent par dap, le breakpoint est honoré Ctrl+⇧+F9
:!mvn -q test Toute la suite, hors éditeur —

Les raccourcis de test sont attachés aux buffers Java, contrairement à ceux du debug : ils n'ont de sens que dans un .java.

Ce qui mord

Trois pièges

  • K n'est pas le hover — il scrolle de 3 lignes. Le hover, c'est H.
  • Lancer nvim ailleurs que depuis la racine du projet donne un workspace jdtls mal nommé.
  • jdtls met 2 à 3 secondes à s'attacher au premier fichier Java : les diagnostics arrivent après.
